# 审查→AC 桥接规范

- 版本：v2.0.0 (2026-08-12)
- 适用：Architect 最终审查 Coder 交付和独立 reviewer 报告

## 1. 审查前置门

Architect 必须独立核实：

1. Coder 执行的是最新任务版本和预期基线。
2. 每个改动文件都在最终自主边界内。
3. 每个非平凡自主决策都有证据支持的决策摘要。
4. 没有决策越过强制升级边界。
5. 每个影响交付的分歧均为 `CLOSED`，且实现基于裁决指定的任务版本。
6. 改变实现行为的裁决有对应测试覆盖。
7. Coder 和 reviewer 只运行验证白名单，鉴权失败/基线债未被绕过。

任何影响交付的未关闭分歧、未纳入新任务版本的口头裁决、Coder 越过强制升级边界的实现，或 reviewer 违反只读/脱敏/共享环境边界，均计为 BLOCKER。该规则先于文件数、行数和 HIGH 阈值短路执行。

## 2. 独立核查范围

- 对任务文档每个 Unit 核对目标、不变量、允许文件、执行模式、依赖和验收命令。
- 对 Git diff 独立确认文件清单、接口契约、依赖、Java 规范和分层红线。
- 对 Coder 报告中的自测命令重新运行或核对可复现输出，不接受无命令的“已通过”。
- 对 PRD/验收每个功能点确认有实现单元覆盖；对未核实项确认是否进入 `INVESTIGATE_FIRST`。
- 对模式 A/B 报告保持双盲，只比较证据、观察和结论，不把 reviewer 多数票当事实证明。

## 3. 严重度与阈值

| 级别 | 定义 |
|------|------|
| BLOCKER | 功能不可用、数据错误、安全漏洞、未关闭交付分歧、协议边界违反 |
| HIGH | 边界/异常行为不正确、偏离批准目标或验收、关键证据缺失 |
| MEDIUM | 小偏差、健壮性不足、非关键测试缺口 |
| LOW | 风格、命名、注释问题 |
| NOTE | 观察、未验证项、建议 |

无 BLOCKER 时保留原有 AC 阈值：文件数 >3、改动行数 >150 或 HIGH ≥3 任一满足，就建议用户确认桥接；全部不超阈值则可通过。

## 4. 结论

### BLOCKER

```text
❌ 审查发现 BLOCKER {N} 个，直接暂停/打回，不进入 AC：
- {D-xxx 或边界违反}：{原生绝对路径 + 符号} — {证据与原因}
期望处理：{Coder 修复 / Architect 更新任务版本 / 用户裁决 / 返回 superpowers}
```

### 通过

```text
✅ 审查通过。任务版本 {vN}，关闭分歧 {N} 个，改动 {文件数} 文件 {行数} 行，HIGH {N} 个，BLOCKER 0 个。
```

### 超阈值（无 BLOCKER）

```text
⚠️ 无 BLOCKER，但超出 AC 阈值：{文件数/行数/HIGH}。建议用户确认后由 codex 和 opencode 执行模式 A 双盲 QA 回归；这不是对未关闭分歧的替代。
```

用户拒绝桥接时记录“已知超阈值风险，用户知悉”，不得标记为无风险通过。

## 5. AC 安装检测与提示词

用户确认后按顺序检测当前 skill 列表、已知 skills 目录、plugin cache 和 `~/.codex/plugins/`。未检测到 multi-reviewer 时说明无法桥接，不能静默跳过。已安装时生成主仓归档的 QA prompt，只给已验证路径、事实、验收目标和白名单命令，不泄露 Architect 判断结论或对方 reviewer 报告。
