# 代码扫描委托规范

- 版本：v2.0.0 (2026-08-12)
- 适用：Architect 在任务合同生成前理解大范围代码
- 目的：把机械扫描委托给低成本 Coder，同时保留 Architect 对决定性事实的独立核实责任

## 1. 何时委托

- 小改动（1–2 个方法、单文件）：Architect 直接读取相关代码。
- 跨模块、跨仓、调用链或字段流较长：可委托一个或多个弱模型扫描。
- 有子 agent 能力时可并行按模块扫描；没有时生成扫描任务文档，交给独立弱模型 session。
- 扫描 agent 只读源码，只将摘要写入 `<repo>/.claude/<slug>/<YYYY-MM-DD>/codebase-scan-<name>.md`，不改源码或执行 Git 写操作。

## 2. 扫描范围

固定覆盖：模块职责、关键符号/签名、调用链、数据流、Schema/配置/依赖、项目内框架 API 用法、影响面和测试入口。跨仓时必须给出真实 Controller → Service → Handler/Repository 路径；不得按命名惯例猜测。

## 3. 证据质量与事实/推断分离

| 状态 | 含义 | 可否直接用于裁决 |
|------|------|------------------|
| `DIRECT` | 已直接读取当前代码、配置、Schema 或依赖元数据 | 可作为证据，关键项仍由裁决者独立复核 |
| `REPRODUCED` | 已运行只读命令、构建、测试或检查并记录结果 | 可作为证据，保留命令与摘要 |
| `INFERRED` | 根据命名、调用邻接或历史资料推断 | 不可直接用于裁决 |
| `UNVERIFIED` | 未访问或访问失败 | 不可写成事实 |

每个决定性主张必须使用原生绝对路径、稳定符号/配置/Schema 或命令作为锚点。行号只能辅助。委托摘要永远不足以单独得出 `ARCHITECT_DECIDED`；Architect 生成任务合同或裁决分歧前必须重读关键代码或复现命令。

## 4. 扫描派发

派发只给已验证的原生绝对扫描任务路径，不内联整篇方案或源码。扫描 agent 查大文档时先用 `rg -n` 命中关键词，再用 `sed -n` 按需读取片段；除非文档是规范入口，不整篇加载。报告末尾返回不超过 200 字的标准化可复制总结。

## 5. 质量门与失败处理

- 摘要缺模块职责、关键签名、调用链、数据流、影响面或证据状态时，不可交付。
- 访问失败标 `UNVERIFIED`，不得补写推断；Architect 可创建 `INVESTIGATE_FIRST` 单元。
- 多份并行摘要冲突时，记录差异并由 Architect 独立核实，不做多数投票。
- 扫描进程和临时服务验完立即关闭，输出脱敏。

## 6. 落盘与增量复用

扫描摘要落在 `<repo>/.claude/<slug>/<YYYY-MM-DD>/`。摘要记录基线 commit、扫描时间和覆盖文件。后续按 `git diff --name-only` 判断增量；变更超出覆盖或约 30% 以上时重新全扫，旧摘要标记过时。跨会话只把摘要当导航，仍需核实决定性事实。

## 7. 与 superpowers 的边界

本规范服务于 cdel 把已批准方案转成任务合同。方案设计仍由 `superpowers:brainstorming` 和 `superpowers:writing-plans` 完成；扫描结果发现设计冲突时返回 superpowers，不由 cdel 自行重设计。
