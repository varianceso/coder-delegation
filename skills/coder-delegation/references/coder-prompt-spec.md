# Coder 编码任务文档规范

- 版本：v2.0.0 (2026-08-12)
- 适用：Architect 生成 Coder 任务合同
- 规范来源：`evidence-dispute-arbitration.md`、`workmode-protocol.md`、`coder-hard-constraints.md`

## 1. 文档定位

任务文档是跨 session 的自包含执行合同，描述目标真相、已核实当前事实、允许文件、自主边界、实现单元、验证白名单、分歧路径和报告路径。它不是把每一行源码写死的补丁脚本。

## 2. 质量门

| 维度 | 要求 |
|------|------|
| 自包含 | Coder 可从任务文档确定目标、边界、证据、命令和报告位置 |
| 可核实 | 关键事实有原生绝对路径 + 稳定符号/命令 + 证据状态 |
| 有界自主 | 每个单元声明模式、允许自主决定和必须升级条件 |
| 可恢复 | 分歧、裁决和任务版本路径明确 |
| 可交付 | 编译、具体测试和检查命令属于验证白名单 |
| 可复制 | 派发提示词只包含已验证的原生绝对任务路径和执行要求 |

## 3. 必需章节

任务必须包含：§0 文档状态、§1 目标真相、§2 已核实当前代码事实、§3 自主决策边界、§4 实现单元、§5 自测要求、§6 分歧/暂停/裁决/恢复、§7 自审、§8 交付报告、§9 Architect 决策记录。Java 任务还必须声明 `java-backend-standard.md` 是否适用及例外。

实际任务文档不得包含 `~`、环境变量、相对路径、`file://` URI、未解析模板变量或混合路径分隔符。Architect 必须按 Coder 环境生成并验证原生绝对路径；环境不明确或文件系统不共享时必须先询问用户。

## 4. §0 文档状态与原生绝对路径

必须填写协议版本、任务版本、任务状态、基线 commit、Coder 运行环境、仓库根目录、本任务文档、PRD/验收、技术方案、执行计划、分歧单和交付报告的原生绝对路径，以及未关闭/已关闭分歧 ID。

## 5. §1 目标真相

记录用户决定、验收标准、PRD 和批准方案的来源与优先级，明确本任务的目标行为、不可改变的产品语义、公共契约和风险承诺。PRD 只读。

## 6. §2 已核实当前代码事实

列出当前入口、调用链、测试、配置、Schema、依赖和项目内 API 用法。每条事实使用：

```markdown
| 原生绝对路径 | 符号/签名/测试/配置 | 事实 | 证据状态 | 核实命令 |
|---|---|---|---|---|
| /repo/src/... | UserService#getUser | 当前由 Controller 调用 | DIRECT | rg -n 'getUser' /repo/src |
```

不得把扫描摘要或历史文档直接当作决定性证据。

## 7. §3 自主决策边界

声明允许文件、关键依赖、允许自主决定、必须升级裁决的行为、验收不变量，以及 Java 规范引用（如适用）。Java 后端任务至少检查命名、参数数量、150 字符行限、分层红线、异常/日志脱敏和 SQL 安全规则。

## 8. §4 实现单元与三种执行模式

每个单元必须包含以下字段：

```markdown
- **单元 ID**：`Unit N`
- **执行模式**：`BOUNDED_AUTONOMY | EXACT_CHANGE | INVESTIGATE_FIRST`
- **依赖单元**：`无` 或明确 Unit ID
- **允许文件**：Coder 环境可访问的原生绝对路径
- **实现目标**：可观察结果
- **必须保持的不变量**：接口、异常、数据、兼容性和安全边界
- **已核实证据锚点**：路径 + 符号/签名/测试/配置/Schema + 事实
- **允许自主决定**：本单元内的局部选择
- **必须升级裁决**：本单元特有升级条件
- **可选实现提示**：仅供参考；EXACT_CHANGE 除外
- **验收检查**：可直接运行的白名单命令和明确结果
```

`EXACT_CHANGE` 必须给出精确动作和精确内容；`INVESTIGATE_FIRST` 必须给出证据问题及继续/停止条件；`BOUNDED_AUTONOMY` 不得写死实现路径。

## 9. §5 自测要求

只列白名单命令。Maven 编译命令应带 `-pl <受影响模块> -am`，测试命令列出具体测试类并用逗号分隔；禁止“相关测试”“顺便回归”和扩大到未改动链路。编译 0 error、白名单测试全 PASS、鉴权失败和基线债如实报告。

## 10. §6 分歧、暂停、裁决与恢复协议

填写分歧单原生绝对路径和状态。发现分歧时暂停受影响单元及依赖；可继续范围必须写独立性依据。Coder 只能从包含分歧 ID、裁决结果和恢复范围的新任务版本恢复。设计冲突回到 superpowers，产品/契约/范围/风险问题询问用户。

## 11. §7 自审 Checklist

嵌入 `coder-hard-constraints.md` 的 10 项 checklist；另加“只跑白名单”“Java 规则适用性已确认”（如适用）和“标准化总结不超过 200 字”。

## 12. §8 交付报告要求

报告写入任务文档指定的原生绝对路径，包含执行版本与基线、实现单元结果、自主决策摘要、分歧和裁决执行、完整脱敏 diff、自测结果、自审状态、未完成/阻塞项和不超过 200 字的可复制总结。存在未关闭交付分歧时只能报告 `BLOCKED`，不得报告 `COMPLETED`。

## 13. §9 Architect 追加式决策记录

Architect 只追加记录，不覆盖历史：时间、分歧 ID、独立证据、裁决者、裁决结果、更新任务版本、恢复范围、验收变化和用户决定记录。

## 14. v1.x `EXACT_CHANGE` 兼容

旧任务继续使用原来的 §3.1 文件清单、动作语义和固定代码块。Coder 将其视为 `EXACT_CHANGE`，不得静默转换成有界自主任务。
